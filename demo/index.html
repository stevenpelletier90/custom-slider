    3 Add the files to the site — once, not per slider

    Once per site, not once per slider. Link the files if you can upload them; paste the code if you can’t. Either way the slider above is running the very ones you would take.

    Link to the files

    Best choice — every page that links them shares one cached copy.

    <link rel="stylesheet" href="/assets/shared/CustomHTMLFiles/Responsive/Apps/customSlider/custom-slider.css">
<script src="/assets/shared/CustomHTMLFiles/Responsive/Apps/customSlider/custom-slider.js" defer></script>
    Two files, that’s all The stylesheet carries the card styling as well, so a slider you copy from here is mostly just its markup. Without these two files linked, a pasted slider is a plain list.
    Where these go Both tags go in the Head Section tab — the one that takes HTML, not “Style Only, Head Section”, which takes raw CSS and would swallow a tag. The <script> can go in Body Section, Bottom instead if you prefer it there.
    The path These live at /assets/shared/CustomHTMLFiles/Responsive/Apps/customSlider/ — one shared copy for every site. Until the current build is uploaded there, that address still serves the old dl-carousel engine, and a slider linked to it renders as a plain list.

    Or paste the code

    For a site where you can’t upload files. What you copy is today’s build — a pasted copy stays on that build, so it has to be pasted again after each update.

    custom-slider.css
    custom-slider.js
    Where these go Copy gives you the wrapper too, so both go in a field that takes HTML: the <style> in Head Section, the <script> in Body Section, Bottom. Not “Style Only” — that field takes raw CSS with no tags and no comments, and this stylesheet has both.
    Or the comment-free pair npm run paste writes dist/paste/1-style-only.css (engine and card styles, comments stripped, for the Style Only field) and dist/paste/2-body-bottom.html. That is the route for a page where you have no file access at all.
