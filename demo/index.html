Custom Slider

Dependency-free scroll-snap slider. Try this page with JavaScript disabled — every variation remains a readable, swipeable strip (the one exception is the fullscreen lightbox, which is modal by nature).

How to use this page: find the look you want below, open the panel underneath it, and copy the HTML and the CSS. Do Start here once per page first — that is what puts the slider on the page at all.

One engine, one stylesheet — 5.9 KB gzipped together, no dependencies and no build step. Only two of the looks below are separate engine modes (data-fade and data-gallery); every other one is the same carousel with different site CSS. With JavaScript off, every strip stays a swipeable scroller with all its content readable — you lose the arrows, dots, autoplay and the gallery's thumbnails.

Options reference

Everything you can switch on is a data attribute on the slider's root element; everything visual is plain CSS. Slides-per-view is CSS too — --dlc-per-view inside your own media queries, no JS breakpoints anywhere.

Data attributes
Attribute Default Effect
data-slider — Auto-initialize this element
data-autoplay="4000" 0 (off) Advance every N ms; adds a pause button
data-rewind="false" rewind on Stop at the ends instead of wrapping; end arrows disable
data-step="slide" page Arrows/autoplay advance one card at a time (see the model bar)
data-fade off Crossfade instead of sliding — one slide at a time (see the hero)
data-drag="false" drag on Opt out of mouse drag-to-scroll (touch swiping is native either way)
data-gallery off Thumbnail-gallery (tabbed) variant
data-init="manual" auto Skip auto-init; construct with new DLCarousel(el) from page script (see the lightbox)
data-roledescription="…" carousel Screen-reader role description; empty string to omit

The most-used --dlc-* CSS knobs are listed in the stock look's copy block; the full list, the events and the JS API are in the README.

One image at a time, each fading into the next. Autoplays every 5 seconds with a pause button. Engine mode: data-fade.

  • Factory-Certified Service Schedule now
What this is, and how to build it

The big rotating banner at the top of a homepage. Instead of sliding sideways, each image dissolves into the next. This is the most common slider on our demo sites by a distance — 68 of the 76 have one — and until now our library could not do it at all.

How it is set up. One image at a time, the whole banner is a link, it changes every 5 seconds, and there are dots to jump between them. The 5 seconds is not a guess: it is what every one of those 68 sites already uses. The images sit stacked on top of each other in one space, so the tallest one sets the height and the page never jumps around as it changes.

Why the alt text is empty. The link already says where it goes ("Summer Sales Event — shop current offers"), so describing the photo as well would make a screen reader announce the same banner twice.

The reason this was worth rebuilding rather than leaving alone: the version on those 68 sites has four accessibility problems, and this one has none of them.

Platform hero (68 sites) This one
The pause button is 16 × 6 pixels — smaller than the accessibility guidelines allow, and named "hidden" in the code A 36 × 36 button, comfortably above the minimum, and the first thing you reach with the Tab key
The dots are list items pretending to be buttons Actual buttons, one per banner
Screen-reader announcements are switched off on the banner A short announcement of which banner you are on — and silence while it is rotating on its own, so it does not chatter
No handling for people who ask their device to reduce motion It simply does not rotate for them, and the dissolve is dropped too

All 76 demo homepages were checked for this, and the banner behaviour was confirmed by watching the real pages rather than reading their code — the pause button, for instance, does not appear in the page source at all, because it is added after the page loads. Full write-up in docs/research/2026-08-18-oem-demo-slider-census.md.

What this is, and how to build it

The row of vehicle cutouts nearly every dealer homepage has. Click a model, land on that model's inventory. It moves one card at a time rather than jumping a whole screenful, the entire card is the link, and there are no dots — just arrows and swipe.

You do not have to guess at any of this. We looked at all 129 OEM demo sites. Ninety of them have a model bar, and they are all built the same way: arrows always on, swipe always on, dots almost never, a sliver of the next card peeking at the edge — and not one of them rotates on its own. That last one is why nothing in this library auto-advances except the homepage banner. If a model bar moved by itself while someone was reading it, it would be working against them. (The only autoplaying strips in the whole estate are one group site's make and location rails — not model bars — shown at the end of the model bar library.)

The only thing that changes brand to brand is how many cards show at each screen size — and there are just twenty combinations across all 90 sites. Find your brand in the table and copy its row — or open the model bar library, where every row runs live with its finished copy-paste pair. Do not work the numbers out yourself: the original sites count their screen sizes downwards and we count upwards, so the figures here are already flipped for you, and re-deriving them by hand is the easiest way to get it wrong.

One more check before you reach for the slider: a few OEMs (Porsche, INFINITI, BMW, one Ford variant) ship their model bar as a static grid or tab panes with no carousel at all — that family lives on the library page too.

What this is, and how to build it

The same model bar, split into groups you switch between — trucks, SUVs, electric, and so on. Use it when a lineup is too long for one row, or when people shop by body style rather than by model name. The background colour shifts as you move between tabs, which is a nice touch borrowed from the Kia demo.

Each tab holds its own separate slider. Add or remove tabs freely — the page works out how many there are. The tabs themselves are a small piece of code on this page, not part of the slider library, so you can restyle them however you like.

One thing that usually causes trouble elsewhere and does not here: a slider inside a hidden tab cannot measure itself, because it has no size yet. Ours notices the moment its tab is shown and measures then, so there is none of the propping-open trickery older slider libraries need.

This is the normal shape, not a Kia quirk. Of the 90 sites with a model bar, 51 group theirs under tabs — usually three to five groups, by body style, fuel type, or (on the multi-brand stores) brand. One warning if you go looking at the originals: nearly every site also has a Buy / Finance / Lease switcher for payments, which is a completely different thing and easy to mistake for these. Copy this. The HTML goes in a Custom HTML block; the CSS goes in the page's Style Only box. Add the slider itself first — once per page.

HTML

<div class="my-tabs" data-tabs>
  <div role="tablist" aria-label="Shop by type">
    <button type="button" role="tab" id="tab-trucks" aria-controls="pane-trucks" aria-selected="true">Trucks</button>
    <button type="button" role="tab" id="tab-suvs" aria-controls="pane-suvs" aria-selected="false" tabindex="-1">SUVs</button>
  </div>

  <div id="pane-trucks" role="tabpanel" aria-labelledby="tab-trucks">
    <div class="my-modelbar dl-carousel" data-slider data-step="slide" aria-label="Trucks">
      <ul class="dl-carousel-track">
        <li class="dl-carousel-slide">...model card...</li>
      </ul>
    </div>
  </div>

  <div id="pane-suvs" role="tabpanel" aria-labelledby="tab-suvs" hidden>
    <div class="my-modelbar dl-carousel" data-slider data-step="slide" aria-label="SUVs">
      <ul class="dl-carousel-track">
        <li class="dl-carousel-slide">...model card...</li>
      </ul>
    </div>
  </div>
</div>

<script>
  // Tab switching. Each pane holds its own slider; they look after themselves.
  addEventListener('DOMContentLoaded', function () {
    document.querySelectorAll('[data-tabs]').forEach(function (wrap) {
      var tabs = Array.prototype.slice.call(wrap.querySelectorAll('[role="tab"]'));
      var panes = tabs.map(function (t) { return document.getElementById(t.getAttribute('aria-controls')); });
      function select(i) {
        tabs.forEach(function (t, j) {
          t.setAttribute('aria-selected', String(i === j));
          t.tabIndex = i === j ? 0 : -1;
          panes[j].hidden = i !== j;
        });
        wrap.dataset.tab = i;
      }
      tabs.forEach(function (t, i) { t.addEventListener('click', function () { select(i); }); });
      wrap.querySelector('[role="tablist"]').addEventListener('keydown', function (e) {
        var i = tabs.indexOf(e.target); if (i === -1) return;
        var n = e.key === 'ArrowRight' ? (i + 1) % tabs.length : e.key === 'ArrowLeft' ? (i - 1 + tabs.length) % tabs.length : null;
        if (n === null) return;
        e.preventDefault(); tabs[n].focus(); select(n);
      });
      select(0);
    });
  });
</script>

What this is, and how to build it

The same lineup in two rows instead of one, so twice as many models fit before anyone has to scroll. One OEM demo site does it this way. Cards fill top-to-bottom and then move to the next column, so reading order stays sensible.

This is CSS only — the slider is untouched. The row of cards becomes a grid two rows deep, and an arrow click moves one full screen at a time as usual. (Leave data-step="slide" off here: the "next card" is the one directly underneath, at the same horizontal position, so a one-card step has nowhere to scroll.)

One number to get right. The slider counts cards, not columns — so tell it how many cards are on screen, which in two rows is columns × 2. Set --dlc-cols to the columns you want and --dlc-per-view to double it. Get that pairing wrong and an arrow click moves half a screen, or nothing at all, because the next card along is the one directly underneath.

Copy this. The HTML goes in a Custom HTML block; the CSS goes in the page's Style Only box. Add the slider itself first — once per page.

HTML

<div class="my-grid dl-carousel" data-slider aria-label="Our lineup">
  <ul class="dl-carousel-track">
    <li class="dl-carousel-slide">...card...</li>
    <li class="dl-carousel-slide">...card...</li>
    <!-- cards fill top-to-bottom, then move to the next column -->
  </ul>
</div>

CSS

/* --dlc-cols = columns on screen. --dlc-per-view = cards on screen, which in
   two rows is columns x 2. The slider counts cards, so this pairing is what
   makes one arrow click move exactly one screen. */
.my-grid { --dlc-cols: 2; --dlc-per-view: 4; --dlc-gap: 1rem; }
@media (min-width: 769px) { .my-grid { --dlc-cols: 3; --dlc-per-view: 6; } }

.my-grid .dl-carousel-track {
  display: grid;
  grid-auto-flow: column;
  grid-template-rows: repeat(2, auto);
  grid-auto-columns: calc((100% - (var(--dlc-cols) - 1) * var(--dlc-gap)) / var(--dlc-cols));
}
.my-grid .dl-carousel-slide { flex: none; }

Peek at the next card

A sliver of the next card stays visible at each edge and fades out. CSS only: --dlc-peek plus a mask. Turn the peek right up and you get a centred card.

What this is, and how to build it

A sliver of the next card stays visible at each edge, fading out as it goes. It is the clearest way to tell someone there is more to scroll without adding anything to the page — people reach for a strip that visibly continues.

Turn the peek right up and you get a centred card. With one card per view and a large peek — say --dlc-peek: 20% — the active card sits dead centre with a slice of the previous and next either side. That is the "centre mode" look some OEM sites use for galleries, and it needs nothing beyond the setting below.

Two settings, no code. --dlc-peek decides how much of the neighbouring card peeks out, and a fade is layered over each edge at the same width so the sliver softens instead of being cut off. Both are CSS. Nothing is added to the page, nothing changes in the slider, and it behaves correctly for people who have asked their device to reduce motion.

Copy this. The HTML goes in a Custom HTML block; the CSS goes in the page's Style Only box. Add the slider itself first — once per page.

HTML

<div class="my-peek dl-carousel" data-slider aria-label="Gallery">
  <ul class="dl-carousel-track">
    <li class="dl-carousel-slide">
      <img src="#MISCPATH#photo-1.jpg" width="1200" height="750" alt="Describe the photo">
    </li>
    <!-- repeat the <li> for each photo -->
  </ul>
</div>

CSS

.my-peek { --dlc-per-view: 1; --dlc-peek: 48px; --dlc-gap: 1rem; }
@media (min-width: 1024px) { .my-peek { --dlc-per-view: 3; } }
.my-peek img { display: block; inline-size: 100%; block-size: auto; aspect-ratio: 4 / 3; object-fit: cover; border-radius: 6px; }

/* Fade the peeking slivers at both edges. The fade width matches --dlc-peek. */
.my-peek .dl-carousel-track {
  mask-image: linear-gradient(to right, transparent, #000 48px, #000 calc(100% - 48px), transparent);
}

What this is, and how to build it

The most common slider on the platform's inner pages: every inventory-results card has one. The card grid is ordinary CSS — no slider involved — and each card holds its own independent one-photo-at-a-time instance. Auto-init picks up every data-slider on the page, so twenty cards are twenty instances with no extra wiring.

The image counter is a page script listening for dlc:change — the standard way to extend the slider without touching the engine. The chip is aria-hidden: the slider already tells screen readers where it is, so the chip is a visual duplicate.

One caution: do not stretch a whole-card link over a card that contains its own controls — the invisible overlay would sit on top of the arrows and swallow their clicks. Keep the card's link a plain link, and let the photos swipe.

Copy this. The HTML goes in a Custom HTML block; the CSS goes in the page's Style Only box. Add the slider itself first — once per page.

HTML

<div class="my-cardgrid">
  <article class="my-vcard">
    <div class="my-vcard-media">
      <div class="my-cardgal dl-carousel" data-slider aria-label="Photos of the 2021 Porsche Panamera">
        <ul class="dl-carousel-track">
          <li class="dl-carousel-slide">
            <img src="#MISCPATH#panamera-1.jpg" width="800" height="500" alt="2021 Porsche Panamera, rear three-quarter view">
          </li>
          <!-- repeat the <li> for each photo of this vehicle -->
        </ul>
      </div>
      <span class="my-cardgal-count" aria-hidden="true"></span>
    </div>
    <h3>2021 Porsche Panamera</h3>
    <p>$82,900 &middot; 18,300 mi</p>
    <a href="/used-inventory/index.htm" aria-label="View details on the 2021 Porsche Panamera">View details</a>
  </article>
  <!-- repeat the <article> for each vehicle -->
</div>

<!-- The counter: one small page script for every card on the page. -->
<script>
  addEventListener('DOMContentLoaded', () => {
    for (const media of document.querySelectorAll('.my-vcard-media')) {
      const root = media.querySelector('.dl-carousel');
      const out = media.querySelector('.my-cardgal-count');
      if (!root || !out) continue;
      const total = root.querySelectorAll('.dl-carousel-slide').length;
      const set = (i) => (out.textContent = i + 1 + ' / ' + total);
      set(0);
      root.addEventListener('dlc:change', (e) => set(e.detail.index));
    }
  });
</script>

Filterable gallery

The same thumbnail gallery with category buttons above it — click one and the gallery narrows to that set. All page script, no engine changes.

What this is, and how to build it

One OEM model page runs six of these — a photo gallery a visitor can narrow by category. Here it is three moving parts: a data-tag on each slide, a row of aria-pressed pill buttons, and a page script that rebuilds the gallery on each click.

The rebuild leans on the public API. destroy() puts the slider's markup back exactly as it was written — every slide present again — so the script starts from the full set each time: destroy, remove the slides that don't match, and let DLCarousel.autoInit() rebuild the gallery (thumbnails included) from what is left.

Copy this. The HTML goes in a Custom HTML block; the CSS goes in the page's Style Only box. Add the slider itself first — once per page.

HTML

<div class="my-filterbar" role="group" aria-label="Filter photos">
  <button type="button" class="my-filter" data-filter="" aria-pressed="true">All</button>
  <button type="button" class="my-filter" data-filter="exterior" aria-pressed="false">Exterior</button>
  <button type="button" class="my-filter" data-filter="interior" aria-pressed="false">Interior</button>
</div>
<div class="my-fgallery dl-carousel" data-slider data-gallery aria-label="Vehicle photos">
  <div class="dl-carousel-track">
    <div class="dl-carousel-slide" data-tag="exterior">
      <img src="#MISCPATH#photo-1.jpg" width="1200" height="750" alt="Describe the photo">
    </div>
    <!-- repeat per photo; data-tag matches a button's data-filter -->
  </div>
</div>

<script>
  addEventListener('DOMContentLoaded', () => {
    const bar = document.querySelector('.my-filterbar');
    const root = document.querySelector('.my-fgallery');
    if (!bar || !root) return;
    let pristine = null;
    bar.addEventListener('click', (e) => {
      const btn = e.target.closest('.my-filter');
      if (!btn) return;
      for (const b of bar.querySelectorAll('.my-filter')) b.setAttribute('aria-pressed', String(b === btn));
      // destroy() restores the markup ITS instance was built from — after a
      // filter that is the pruned set — so capture the full authored markup
      // once (the first destroy restores it) and rebuild from that copy.
      root._dlCarousel?.destroy();
      pristine ??= root.innerHTML;
      root.innerHTML = pristine;
      const tag = btn.dataset.filter;
      if (tag) for (const s of root.querySelectorAll('.dl-carousel-slide')) if (s.dataset.tag !== tag) s.remove();
      DLCarousel.autoInit(root.parentElement);
    });
  });
</script>

Fullscreen gallery in a dialog

The VDP pattern: a small opener on the page, the full gallery in a modal. The gallery initializes on first open, while the dialog is visible.
What this is, and how to build it

Every vehicle detail page opens its photos in a fullscreen viewer, and this is that shape: a native <dialog> (Esc and focus containment come free, exactly like the video modal) with a thumbnail gallery inside it.

The one new idea is data-init="manual". A closed dialog is display: none, so a gallery built at page load would measure a box that isn't there. The attribute tells auto-init to skip it; the open button calls new DLCarousel(root) on first open, after showModal(), so every measurement is taken while the dialog is visible. One honest caveat: this is the only pattern on this page that needs JavaScript to show its content at all — with JS off, the opener does nothing and the dialog stays closed. The photos still ship in the HTML (search engines see them), but a no-JS visitor cannot. Keep a lightbox for extra photos, never for the only copy of something.

What this is, and how to build it

Customer video testimonials — a still frame with a play button on the left, the person's name and their story on the right. The video never plays in the card itself. Clicking either the picture or "Click to watch" opens it in a pop-up over the page, which you close with the ✕, the Esc key, or by clicking the dark area around it.

Making the video actually stop. This is the part that catches people out. Closing the pop-up hides the video but does not stop it, so you get a voice still talking from nowhere. There is no way to press pause on a YouTube video from outside it without loading YouTube's own extra code, so instead we take the video address away when the pop-up closes, which stops it dead.

The other half matters just as much: we listen for the pop-up closing, rather than for the ✕ being clicked. Wire it to the ✕ alone and it looks fine in testing — but pressing Esc or clicking outside leaves the audio playing, which is exactly the bug that was reported.

Swapping in your own video: change the video id on the two buttons in each card. Nothing else needs touching. The demo uses Big Buck Bunny, an openly licensed short film, so there is no copyrighted footage sitting in a public demo. The cards themselves do not rotate on their own — the site we based this on flips through them every 3 seconds, which fights you when you are trying to read one.

Copy this. The HTML goes in a Custom HTML block; the CSS goes in the page's Style Only box. Add the slider itself first — once per page.

<script>
  // Opens the pop-up and - the important half - stops the video on close.
  addEventListener('DOMContentLoaded', function () {
    var dialog = document.getElementById('video-dialog');
    if (!dialog) return;
    var title = dialog.querySelector('.my-video-title');
    var embed = dialog.querySelector('.my-video-embed');
    document.querySelectorAll('[data-video-id]').forEach(function (btn) {
      btn.addEventListener('click', function () {
        title.textContent = btn.dataset.videoTitle;
        embed.src = 'https://www.youtube-nocookie.com/embed/' + btn.dataset.videoId + '?autoplay=1&rel=0';
        dialog.showModal();
      });
    });
    dialog.querySelector('.my-video-close').addEventListener('click', function () { dialog.close(); });
    dialog.addEventListener('click', function (e) { if (e.target === dialog) dialog.close(); });
    // Listen for the dialog CLOSING, not for the X being clicked - otherwise
    // Esc and clicking outside leave the audio playing.
    dialog.addEventListener('close', function () { embed.removeAttribute('src'); });
  });
</script>
