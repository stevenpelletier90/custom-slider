What this is, and why we rebuilt it

The big rotating banner at the top of a homepage. Instead of sliding sideways, each image dissolves into the next. This is the most common slider on our demo sites by a distance — 68 of the 76 have one — and until now our library could not do it at all.

How it is set up. One image at a time, the whole banner is a link, it changes every 5 seconds, and there are dots to jump between them. The 5 seconds is not a guess: it is what every one of those 68 sites already uses. The images sit stacked on top of each other in one space, so the tallest one sets the height and the page never jumps around as it changes.

Why the alt text is empty. The link already says where it goes ("Summer Sales Event — shop current offers"), so describing the photo as well would make a screen reader announce the same banner twice.

The reason this was worth rebuilding rather than leaving alone: the version on those 68 sites has four accessibility problems, and this one has none of them.

Platform hero (68 sites) This one
The pause button is 16 × 6 pixels — smaller than the accessibility guidelines allow, and named "hidden" in the code A 36 × 36 button, comfortably above the minimum, and the first thing you reach with the Tab key
The dots are list items pretending to be buttons Actual buttons, one per banner
Screen-reader announcements are switched off on the banner A short announcement of which banner you are on — and silence while it is rotating on its own, so it does not chatter
No handling for people who ask their device to reduce motion It simply does not rotate for them, and the dissolve is dropped too

All 76 demo homepages were checked for this, and the banner behaviour was confirmed by watching the real pages rather than reading their code — the pause button, for instance, does not appear in the page source at all, because it is added after the page loads. Full write-up in docs/research/2026-08-18-oem-demo-slider-census.md.

What this is, and how to build it

Card images need width/height (that is what holds CLS at 0) and, on a real site, srcset/sizes — size sizes to ONE slide's rendered width, never 100vw. The six photos on this page are single full-size JPEGs, which is why the demo weighs ~1.8 MB; a responsive set is the single biggest performance win when you implement.

The whole card is clickable via a stretched link: the card's "View details" <a> carries an ::after overlay. Watch the containing block — here the link sits inside the absolutely-positioned card body, so the overlay's top offset overshoots (inset: -999px 0 0) and the card's overflow: hidden trims the hit area to the card box. Keep the link's aria-label short — it is the card's accessible name.

Set slides-per-view in CSS (no JS breakpoints):

Data attributes
Attribute Default Effect
data-slider — Auto-initialize this element
data-autoplay="4000" 0 (off) Advance every N ms; adds a pause button
data-rewind="false" rewind on Stop at the ends instead of wrapping; end arrows disable
data-step="slide" page Arrows/autoplay advance one card at a time (see the model bar)
data-drag="false" drag on Opt out of mouse drag-to-scroll (touch swiping is native either way)
data-gallery off Thumbnail-gallery (tabbed) variant
data-roledescription="…" carousel Screen-reader role description; empty string to omit

What this is, and how to build it

Tall photo cards with the model name over the image — good for a "browse the lineup" row when you want photography rather than cutouts. It stops at the last card instead of looping back to the start, so the arrow greys out when you reach the end.

This is the plain slider underneath. Nothing here is a special mode — every difference you can see is ordinary CSS on top: the arrows are moved out into the margins and made see-through, the cards are portrait instead of landscape, and the row of dots is restyled into a bar with a marker that slides along it. That sliding marker is the one clever bit: a small script on this page watches which dot the slider marks as current and moves the bar to match. If you want something similar, that pattern is the way to do it — you never have to change the slider itself.

One thing to get right on a real site. These photos are placeholders, so they have empty alt text and the heading does the naming. With real vehicle photography, describe the image properly (alt="2026 Chevrolet Silverado 1500 LT in Summit White") so it can turn up in image search — and then give the link that wraps the card a short label of its own, like aria-label="Explore the Silverado". Otherwise a screen reader reads the full photo description and the heading together every time, which gets tiring fast.

What this is, and how to build it

The row of vehicle cutouts nearly every dealer homepage has. Click a model, land on that model's inventory. It moves one card at a time rather than jumping a whole screenful, the entire card is the link, and there are no dots — just arrows and swipe.

You do not have to guess at any of this. We looked at all 76 OEM demo sites. Fifty-five of them have a model bar, and they are all built the same way: arrows always on, swipe always on, dots almost never, a sliver of the next card peeking at the edge — and not one of them rotates on its own. That last one is why nothing in this library auto-advances except the homepage banner. If a model bar moved by itself while someone was reading it, it would be working against them.

What this is, and how to build it

The same model bar, split into groups you switch between — trucks, SUVs, electric, and so on. Use it when a lineup is too long for one row, or when people shop by body style rather than by model name. The background colour shifts as you move between tabs, which is a nice touch borrowed from the Kia demo.

Each tab holds its own separate slider. Add or remove tabs freely — the page works out how many there are. The tabs themselves are a small piece of code on this page, not part of the slider library, so you can restyle them however you like.

One thing that usually causes trouble elsewhere and does not here: a slider inside a hidden tab cannot measure itself, because it has no size yet. Ours notices the moment its tab is shown and measures then, so there is none of the propping-open trickery older slider libraries need.

This is the normal shape, not a Kia quirk. Of the 55 sites with a model bar, 30 group theirs under tabs — usually three to five groups, by body style or fuel type. One warning if you go looking at the originals: nearly every site also has a Buy / Finance / Lease switcher for payments, which is a completely different thing and easy to mistake for these.   <div id="pane-trucks" role="tabpanel" aria-labelledby="tab-trucks">
    <div class="my-modelbar dl-carousel" data-slider data-step="slide" aria-label="Trucks">
      <ul class="dl-carousel-track">
        <li class="dl-carousel-slide">...model card...</li>
      </ul>
    </div>
  </div>

  <div id="pane-suvs" role="tabpanel" aria-labelledby="tab-suvs" hidden>
    <div class="my-modelbar dl-carousel" data-slider data-step="slide" aria-label="SUVs">
      <ul class="dl-carousel-track">
        <li class="dl-carousel-slide">...model card...</li>
      </ul>
    </div>

<script>
  // Tab switching. Each pane holds its own slider; they look after themselves.
  addEventListener('DOMContentLoaded', function () {
    document.querySelectorAll('[data-tabs]').forEach(function (wrap) {
      var tabs = Array.prototype.slice.call(wrap.querySelectorAll('[role="tab"]'));
      var panes = tabs.map(function (t) { return document.getElementById(t.getAttribute('aria-controls')); });
      function select(i) {
        tabs.forEach(function (t, j) {
          t.setAttribute('aria-selected', String(i === j));
          t.tabIndex = i === j ? 0 : -1;
          panes[j].hidden = i !== j;
        });
        wrap.dataset.tab = i;
      }
      tabs.forEach(function (t, i) { t.addEventListener('click', function () { select(i); }); });
      wrap.querySelector('[role="tablist"]').addEventListener('keydown', function (e) {
        var i = tabs.indexOf(e.target); if (i === -1) return;
        var n = e.key === 'ArrowRight' ? (i + 1) % tabs.length : e.key === 'ArrowLeft' ? (i - 1 + tabs.length) % tabs.length : null;
        if (n === null) return;
        e.preventDefault(); tabs[n].focus(); select(n);
      });
      select(0);
    });
  });
</script>

Faded peek

What this is, and how to build it

A sliver of the next card stays visible at each edge, fading out as it goes. It is the clearest way to tell someone there is more to scroll without adding anything to the page — people reach for a strip that visibly continues.

Turn the peek right up and you get a centred card. With one card per view and a large peek — say --dlc-peek: 20% — the active card sits dead centre with a slice of the previous and next either side. That is the "centre mode" look some OEM sites use for galleries, and it needs nothing beyond the setting below.

Two settings, no code. --dlc-peek decides how much of the neighbouring card peeks out, and a fade is layered over each edge at the same width so the sliver softens instead of being cut off. Both are CSS. Nothing is added to the page, nothing changes in the slider, and it behaves correctly for people who have asked their device to reduce motion.

Copy this. The HTML goes in a Custom HTML block; the CSS goes in the page's Style Only box. Add the slider itself first — once per page.

HTML

<div class="my-peek dl-carousel" data-slider aria-label="Gallery">
  <ul class="dl-carousel-track">
    <li class="dl-carousel-slide">
      <img src="#MISCPATH#photo-1.jpg" width="1200" height="750" alt="Describe the photo">
    </li>
    <!-- repeat the <li> for each photo -->
  </ul>
</div>

CSS

.my-peek { --dlc-per-view: 1; --dlc-peek: 48px; --dlc-gap: 1rem; }
@media (min-width: 1024px) { .my-peek { --dlc-per-view: 3; } }
.my-peek img { display: block; inline-size: 100%; block-size: auto; aspect-ratio: 4 / 3; object-fit: cover; border-radius: 6px; }

}

Why the mismatched images still line up

Every image above is a different shape — tall, wide, square — and the row still looks tidy. That is deliberate: dealers upload whatever they have, and the layout should not fall apart because one photo came in portrait.

The trick is to fix the frame, not the photo. Each card gets a fixed-shape box, and the image fills it and is trimmed at the edges to fit:

aspect-ratio: 4 / 3;
inline-size: 100%;
object-fit: cover;

Two things worth knowing. Trimming to fit means the edges of an off-shape photo get cropped, so a subject right at the edge can lose its head — matching artwork still looks better than rescued artwork, so use consistent sizes when you can. And for cutouts or logos, swap cover for contain: those need to sit whole inside the box, not be trimmed. Keep the width and height on every image either way, so the page does not jump around while it loads.

What this is, and how to build it

The model bar's behaviour with proper content cards — a picture, a heading, a line of copy. Good for services, departments, or anything that needs a sentence of explanation rather than just a name. The whole card is clickable and it moves one card at a time.

The cards match heights on their own. You do not have to set a height or trim your copy — a short card stretches to match the tallest one in the row, and every "Read more" still lines up along the bottom. Images go in a fixed-shape frame, so any upload size fits without you cropping anything first.

A mistake worth knowing about, because it is easy to repeat. These cards used to carry a short hidden label — "Learn about the service center" — while the visible text said "Service Center" and then a sentence about it. That fails an accessibility rule: someone using voice control says what they can see, and if the hidden label does not contain those words, nothing happens when they say it.

The fix is to remove the hidden label, not to reword it. The card's description sits inside the link, so no short label could ever contain everything you can see. A short hidden label is fine where the only visible text is a heading — the model bar cards are a good example, where "Explore the Silverado 1500" does contain "Silverado 1500". Automated checks do flag this, but it does not count towards the score, so the page can report a perfect 100 while still failing it.

What this is, and how to build it

Customer video testimonials — a still frame with a play button on the left, the person's name and their story on the right. The video never plays in the card itself. Clicking either the picture or "Click to watch" opens it in a pop-up over the page, which you close with the ✕, the Esc key, or by clicking the dark area around it.

Making the video actually stop. This is the part that catches people out. Closing the pop-up hides the video but does not stop it, so you get a voice still talking from nowhere. There is no way to press pause on a YouTube video from outside it without loading YouTube's own extra code, so instead we take the video address away when the pop-up closes, which stops it dead.

The other half matters just as much: we listen for the pop-up closing, rather than for the ✕ being clicked. Wire it to the ✕ alone and it looks fine in testing — but pressing Esc or clicking outside leaves the audio playing, which is exactly the bug that was reported.

Swapping in your own video: change the video id on the two buttons in each card. Nothing else needs touching. The demo uses Big Buck Bunny, an openly licensed short film, so there is no copyrighted footage sitting in a public demo. The cards themselves do not rotate on their own — the site we based this on flips through them every 3 seconds, which fights you when you are trying to read one.

        </div>
      </article>
    </li>
    <!-- repeat the <li> for each testimonial -->
  </ul>

<!-- The pop-up player, once per page -->
<dialog class="my-video-dialog" id="video-dialog" aria-label="Video player">
  <div class="my-video-head">
    <h3 class="my-video-title">Video</h3>
    <button type="button" class="my-video-close" aria-label="Close video">&#10005;</button>
  </div>
  <div class="my-video-frame">
    <iframe class="my-video-embed" title="Video player" allow="autoplay; encrypted-media; picture-in-picture" allowfullscreen></iframe>
  </div>
</dialog>

<script>
  // Opens the pop-up and - the important half - stops the video on close.
  addEventListener('DOMContentLoaded', function () {
    var dialog = document.getElementById('video-dialog');
    if (!dialog) return;
    var title = dialog.querySelector('.my-video-title');
    var embed = dialog.querySelector('.my-video-embed');
    document.querySelectorAll('[data-video-id]').forEach(function (btn) {
      btn.addEventListener('click', function () {
        title.textContent = btn.dataset.videoTitle;
        embed.src = 'https://www.youtube-nocookie.com/embed/' + btn.dataset.videoId + '?autoplay=1&rel=0';
        dialog.showModal();
      });
    });
    dialog.querySelector('.my-video-close').addEventListener('click', function () { dialog.close(); });
    dialog.addEventListener('click', function (e) { if (e.target === dialog) dialog.close(); });
    // Listen for the dialog CLOSING, not for the X being clicked - otherwise
    // Esc and clicking outside leave the audio playing.
    dialog.addEventListener('close', function () { embed.removeAttribute('src'); });
  });
</script>

What this is, and how to build it

The same lineup in two rows instead of one, so twice as many models fit before anyone has to scroll. One OEM demo site does it this way. Cards fill top-to-bottom and then move to the next column, so reading order stays sensible.

This is CSS only — the slider is untouched. The row of cards becomes a grid two rows deep, and the arrows move one column at a time as usual.

One number to get right. The slider counts cards, not columns — so tell it how many cards are on screen, which in two rows is columns × 2. Set --dlc-cols to the columns you want and --dlc-per-view to double it. Get that pairing wrong and an arrow click moves half a screen, or nothing at all, because the next card along is the one directly underneath.

Copy this. The HTML goes in a Custom HTML block; the CSS goes in the page's Style Only box. Add the slider itself first — once per page.

HTML

<div class="my-grid dl-carousel" data-slider data-step="slide" aria-label="Our lineup">
  <ul class="dl-carousel-track">
    <li class="dl-carousel-slide">...card...</li>
    <li class="dl-carousel-slide">...card...</li>
    <!-- cards fill top-to-bottom, then move to the next column -->
  </ul>
</div>

CSS

/* --dlc-cols = columns on screen. --dlc-per-view = cards on screen, which in
   two rows is columns x 2. The slider counts cards, so this pairing is what
   makes one arrow click move exactly one screen. */
.my-grid { --dlc-cols: 2; --dlc-per-view: 4; --dlc-gap: 1rem; }
@media (min-width: 769px) { .my-grid { --dlc-cols: 3; --dlc-per-view: 6; } }

.my-grid .dl-carousel-track {
  display: grid;
  grid-auto-flow: column;
  grid-template-rows: repeat(2, auto);
  grid-auto-columns: calc((100% - (var(--dlc-cols) - 1) * var(--dlc-gap)) / var(--dlc-cols));
}
.my-grid .dl-carousel-slide { flex: none; }
